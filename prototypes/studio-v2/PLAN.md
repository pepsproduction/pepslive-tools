# PepsProduction — Live in every moment

## เป้าหมายของแผนใหม่

ให้ผู้ชมเข้าใจฝีมือ PepsProduction จากการลองกำกับภาพ และเห็นผลงานจริงต่อเนื่องในหน้าเดียว ใช้ทั้งสามไลบรารีในประสบการณ์ที่สัมพันธ์กัน โดยไม่เพิ่มเอฟเฟกต์ให้ทุกส่วนจนอ่านหรือใช้งานลำบาก

## สถานะงาน — 2026-10-27

งานออกแบบ พัฒนา เชื่อมข้อมูล และผสานหน้า Experience เข้าหน้าเว็บหลักเสร็จแล้ว เผยแพร่ผ่าน Cloudflare Worker รุ่น `2c337650-8408-4354-8829-991433df6350` และตรวจบนเว็บจริงที่ viewport 2560×889 แล้ว ฉาก 3D กับแผงควบคุมอยู่ในกรอบโดยไม่ล้นแนวนอน

สิ่งที่ยังรอหลักฐานจากสภาพแวดล้อมจริงคือการวัดสมรรถนะบนโทรศัพท์/OBS Browser Source, การจำลอง WebGL context loss และการยืนยันรอบ Cron YouTube บน production ดูสถานะละเอียดใน [VERIFICATION.md](VERIFICATION.md)

## ลำดับงาน

1. **กำหนดประสบการณ์และภาพหลัก:** Hero แบบ editorial พื้นเข้ม ตัวอักษรใหญ่ ฉากสตูดิโอ 3D ลอยตัวพร้อมจอผลงานจริง ออกแบบสัดส่วน Desktop และ Mobile พร้อมกัน
2. **ทำแกนเทคนิคที่ใช้งานได้:** React Three Fiber เรนเดอร์กล้อง/จอ/คอนโซล; Shader Gradient สร้างแสงพื้นหลัง; Liquid Glass JS หักเหภาพ shader ผ่าน adapter ที่รับ canvas โดยตรง
3. **เชื่อมการโต้ตอบ:** โหมดสนาม/เวที/สตูดิโอเปลี่ยน palette และมุมฉาก; เดโมฟุตบอลจำลองเปลี่ยนกล้อง สกอร์ และ replay; ตัวควบคุมใช้ HTML ที่คีย์บอร์ดเข้าถึงได้
4. **จัดเนื้อหาจริง:** ผลงานจาก site-content.json, ตัวกรองกีฬา/อีเวนต์, รายละเอียดงาน, Launcher และช่องทางติดต่อเดิม ลิงก์ผลงานเปิดต้นฉบับ YouTube
5. **ตรวจคุณภาพต้นแบบ:** build แบบ static, browser console, interaction, viewport แคบ, reduced motion, หยุดวาดเมื่อพ้นจอ และ fallback เมื่อ WebGL ใช้ไม่ได้
6. **ผสานกับหน้าเว็บหลัก:** ฝัง Hero และ Director ในหน้า `index.html` ด้วย mount แยกพื้นที่ คงระบบผลงาน/ถ่ายทอดสด/วิดีโอ/Calendar/analytics เดิม และดึง contact ทั้ง 7 รายการจาก `site-content.json`; สร้าง bundle ลง `assets/studio-v2/` ในขั้น build เดิม
7. **ตรวจรับก่อนเผยแพร่:** build แบบ static และเช็กปุ่ม, console, จอมือถือ, contact, API hooks และ static asset paths บนเว็บหลัก; การเผยแพร่ Production เป็นขั้นแยกหลังตรวจรับ

## ขอบเขตและเกณฑ์รับงาน

- โค้ดต้นทางของประสบการณ์อยู่ใน `prototypes/studio-v2`; build ของเว็บหลักนำ component ไปใช้ใน `index.html` และสร้าง bundle ใน `assets/studio-v2/` โดยรักษา API, analytics, ข้อมูลคิวงาน และระบบเผยแพร่เดิม
- ฉากบอล คะแนน และ replay เป็นการจำลอง ไม่อ้างว่าเป็นการแข่งขันสดหรือฟีเจอร์ของสินค้าที่ทดสอบแล้ว
- ไม่มีการแต่งยอดผู้ใช้ รีวิวลูกค้า หรือรายการคิวงาน
- ปุ่มจริงต้องให้ผลจริง มี focus state และ aria-pressed; ปุ่มที่ไม่พร้อมจะไม่แสดงหลอก
- แยกโหลดฉากหนัก ใช้ภาพสำรองและปุ่มเปิด 3D เมื่อเหมาะสม; ปิด loop เมื่อ tab ซ่อนหรือ scene พ้น viewport
- หน้า prototype ไม่ยิง analytics เดิมและไม่อ่านข้อมูลปฏิทินส่วนตัว
- การนำไปใช้จริงจะรักษา data hooks, การเข้าถึง, ลิงก์ดาวน์โหลด และเส้นทาง static แบบ relative; การเผยแพร่เป็นขั้นหลังตรวจรับ
